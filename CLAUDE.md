# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Web UI dashboard for a multi-repository workspace manager for Claude Code. Browser interface on `localhost:3741` to view workspace status, TODO progress, reviews, git history, and trigger operations (init, execute, review, create-pr, autonomous, etc.) that run Claude Code via `Bun.spawn` + `claude -p --output-format stream-json`. WebSocket chat server on port 3742 for interactive Claude sessions.

## Commands

```bash
bunx github:sters/ai-workspace-v2 [/path/to/ai-workspace]  # Run via bunx
bun install                                                  # Install dependencies
bun run dev:hot                                              # Development with hot reload
bun run start:build                                          # Production build + start (bun run build && bun run start)
bun run lint                    # next typegen, then tsc --noEmit (tsconfig.typecheck.json) AND eslint src/
bun run test                    # Run all tests
bun run test:watch              # Run tests in watch mode
bun --bun vitest run src/__tests__/lib/parsers/todo.test.ts  # Single test file (--bun is required for bun:sqlite)
```

## Configuration

Per-workspace config in `{workspaceRoot}/.ai-workspace/config.yml`. Priority: env vars > config.yml > defaults. Resolution in `src/lib/config/resolver.ts`, cached on `globalThis`. Workspace root is resolved first (CLI arg > `AIW_WORKSPACE_ROOT` > cwd); the config directory derives from it (`src/lib/config/workspace-dir.ts`).

| Variable | Default | Description |
|----------|---------|-------------|
| `AIW_WORKSPACE_ROOT` | cwd | ai-workspace root (must contain `workspace/` and `repositories/`) |
| `AIW_PORT` | 3741 | Next.js server port |
| `AIW_CHAT_PORT` | 3742 | WebSocket chat server port |
| `AIW_CLAUDE_PATH` | auto-detect | Custom Claude CLI path |
| `AIW_DISABLE_ACCESS_LOG` | `false` | Silence Next.js dev access logs (also `server.disableAccessLog`) |

- `operations.maxGroupConcurrency` (default 8) — max Claude children started at once **within one parallel group** (per group, so it multiplies with `maxConcurrent`). Read via `getMaxGroupConcurrency()` (`src/lib/pipeline/constants.ts`), the single source for both group runners.
- `operations.batchSize` (default 15) — actionable top-level TODO groups (`[ ]` / `[~]`; `[!]` excluded, see `batchTodoGroups` in `src/lib/parsers/todo.ts`) per executor call. With a single batch, `execute.ts` sends the whole TODO file without the "Current Batch" restriction and without per-batch re-reads.
- Execute budget: `executePhaseBudgetMs(batchCount, batchSize)` = `batchCount * batchSize * PER_ITEM_BUDGET_MS + 5min` (`constants.ts`). It is the single source for both `buildExecutePipeline` and autonomous's `executeCycleBudgetMs()` (which uses `ROUTINE_BATCH_COUNT`). `CYCLE_BUDGETS_MS` therefore has no `execute` entry — the wrapper budget is the one that applies under autonomous (see Gotchas).
- `openers: { name, command }[]` — "Open in..." dropdown. Legacy `editor`/`terminal` keys are migrated in `normalizeRawConfig`.
- `model` / `effort` — global, per operation type, and per step (`operations.<type>.steps.<step>.{model,effort}`). `null` falls through to the code-level default (see **Model / effort resolution**). The generated config.yml's defaults comment comes from `TYPE_OVERRIDE_HINT_LINES` (`src/lib/config/migration.ts`); update it when defaults change.
- `operations.defaultInteractionLevel` (`low` / `mid` / `high`, default `mid`) — filled in by `applyOperationDefaults` (`src/lib/validate.ts`) since the UI sends none. API callers (Slack bot, PR Triage) send `low` explicitly.
- Other sections: `hooks.{sessionStartGitContext,blockDangerousBash}`, `suggest.enabled` (post-operation workspace suggestions), `slack.{enabled,botToken,appToken,allowedUserIds,chatModel,chatEffort,chatHeartbeatMs,chatMaxTurnMs,chatProgressModel,memoryEnabled}`.
- **Env substitution** — any string value may contain `{ENV:VAR_NAME}` (uppercase/digits/underscore), replaced at load time (`src/lib/config/env-substitution.ts`); missing vars become `""` with a warning. Use for secrets.

## Architecture

**Next.js 16 App Router**, React 19, TypeScript strict, Tailwind CSS 4, SWR. Bun runtime.

### Core

- **SQLite** — `{workspaceRoot}/.ai-workspace/db.sqlite` via `bun:sqlite`; singleton on `globalThis` (`src/lib/db/connection.ts`). Events buffered and flushed every 5000ms or 50 events (`src/lib/db/event-buffer.ts`).
- **Pipeline orchestration** — an operation is a sequence of `PipelinePhase`s (single child, parallel group, or TypeScript function). Entry: `startOperationPipeline()` (`src/lib/pipeline/orchestrator.ts`); max 3 concurrent operations; definitions in `src/lib/pipelines/`. Function phases may `appendPhases()` (the loop re-reads `phases.length`). `runSubPhases()` (`pipelines/actions/run-sub-phases.ts`) runs a sub-pipeline inside a function phase. Operations interrupted by a shutdown are **not** resumed: `failStaleOperations()` (`pipeline/cleanup-stale.ts`) settles them on restart.
- **Function phase context** — `PhaseFunctionContext`: `emitStatus`, `emitResult`, `emitAsk` (blocks for an answer), `runChild` / `runChildGroup`, `emitTerminal`, `appendPhases`, `setWorkspace`, `signal`. Children accept `allowedTools` (replaces the patterns `addDirs` would generate), `appendSystemPromptFile`, `stepType`, `skipAskUserQuestion`. Function-phase output is auto-tagged with `childLabel = phaseLabel` so it renders as a boxed section.
- **Phase update markers** — `"__phaseUpdate:"` / `"__setWorkspace:"` status prefixes, parsed by `parsePhaseUpdatesFromEvents()` / `parsePhaseUpdatesFromEntries()`; there is no phases table.
- **Phase retries** — `maxRetries` (default 2), `retryDelayMs` (default 3000). A retry reuses the same budget. A user kill aborts `managed.abortController` and stops further attempts; per-phase timeouts use separate AbortControllers. Do **not** detect interruption by matching `[Request interrupted by user]` — the CLI prints it on any SIGTERM, including the pipeline's own timeout kill.
- **Parallel group concurrency** — `runGroupPhase()` (`phase-runners.ts`) and `ctx.runChildGroup()` (`context-builder.ts`) each build a FIFO `Semaphore` sized by `getMaxGroupConcurrency()`; children start in array order, so position decides start order (`review.ts` puts `review-cross-repository`, the longest child, first).
- **Claude CLI** — `src/lib/claude/cli.ts` spawns `claude -p --output-format stream-json`; `AskUserQuestion` handled via `--resume {session_id}`.
- **SSE** — `/api/events?operationId=` streams and replays operation events.
- **Instrumentation split** — `src/instrumentation.ts` delegates to `src/instrumentation-node.ts` to keep Node-only imports out of the Edge runtime.
- **Zod** — `src/lib/schemas.ts` for HTTP bodies, `src/lib/runtime-schemas.ts` for untrusted runtime data. Keep them separate.
- **Process layout** — `bin/start.ts` spawns Next.js (`bin/next-server.ts`), the chat server (`bin/chat-server.ts`), and optionally the Slack bot (`bin/slack-server.ts`, when `slack.enabled` + tokens). `--hot` propagates to all three; a reload keeps chat PTYs and sessions (stored on `globalThis`), but per-session closures keep their old code. Each entry registers process-level state (signal handlers, timers, the Slack Socket Mode connection) **once**, guarded on `globalThis`; `bin/slack-server.ts` stops the previous connection before opening another.
- **Model / effort resolution** — `resolveModel()` / `resolveEffort()` (`src/lib/config/model.ts`): explicit > per-operation per-step config > per-operation config > global > `STEP_DEFAULT_MODELS` / `STEP_DEFAULT_EFFORTS` > CLI default. Effort is the primary cost dial. The two tables cover the same step types (`effort.test.ts`) and form a four-rung ladder; a new step must land on an existing rung (tests reject a fifth pairing, and `model.test.ts` enforces sonnet ⇒ `low`). Place a step by the *shape* of its work (no checklist ⇒ high), not its importance. `code-review` sits at medium for latency; raise per workload via config. `xhigh` / `max` are never code defaults.

  | rung | steps |
  |---|---|
  | sonnet / low — mechanical | `prune-suggestions`, `collect-reviews`, `verify-todo`, `deep-search`, `aggregate-suggestions` |
  | opus / low — shallow judgment | `discover-constraints`, `create-pr`, `readme-clarity-gate`, `best-of-n-file-reviewer`, `best-of-n-synthesizer`, `verify-fixes` |
  | opus / medium — default | `execute`, `code-review`, `verify-readme`, `criteria-feasibility`, `validate-pr-comment`, `ground-finding`, `resolve-conflicts`, `update-readme`, `plan-todo-from-review`, `review-todos`, `suggest-workspace` |
  | opus / high — open-ended | `analyze-readme`, `plan-todo`, `research`, `coordinate-todos`, `best-of-n-reviewer`, `autonomous-gate`, `update-todo` |

- **Best-of-N** — `buildBestOfNPipeline()` (`pipelines/best-of-n.ts`) runs N candidates then a synthesizer; `bestOfN` in config (per-type overrides).
- **Auto-managed hooks** — `src/lib/claude/hooks/sync.ts` writes `.claude/settings.local.json` entries and `.claude/hooks/aiw-*.sh` on startup. Managed entries carry the `aiw-` prefix; others are preserved. `SessionStart` injects `git branch` + `git status --short`; `PreToolUse(Bash)` blocks `rm -rf /...`, `git push --force` without `--force-with-lease`, `git reset --hard`.

### Workspaces and repositories

- **README done-contract** — the workspace README (`src/lib/templates/readme.ts`) defines done via `## Goal`, `## Non-Goal`, `## Assumptions`, `## Requirements`, `## Acceptance Criteria`. Criteria are checkboxes tagged `(auto)` or `(manual)` (untagged ⇒ auto), parsed by `parseAcceptanceCriteria()` (`parsers/readme.ts`). The verifier marks `manual` as `PENDING-HUMAN`; the gate loops only on unmet actionable `auto` criteria and never attempts `## Non-Goal` items. `init-readme.ts` must ground these in the request and record guesses under `## Assumptions`.
- **Repository setup** — `setupRepository` / `setupRepositories` (`pipelines/actions/setup-repository.ts`). `repo:alias` gives a second worktree of one clone (`<path>___<alias>`). `setupRepositories` clones/fetches each clone **once**, then creates worktrees up to 4 at a time: branch creation and `worktree add --no-checkout` are serialized per clone (`withCloneLock` — concurrent `worktree add -b` fail on the `.git/config` lock), and the checkout (`reset --hard`) runs in parallel. Each request gets its own outcome. A failed fetch retries (`FETCH_RETRY_DELAYS_MS`) then proceeds on the refs on disk; a failed clone is fatal. Init's `Setup workspace` uses `SETUP_WORKSPACE_TIMEOUT_MS` (15 min).
- **Quick create** — `/new/quick` (`QuickCreateForm` → `POST /api/workspaces` → `createQuickWorkspace`, `workspace/quick-create.ts`) creates the workspace and worktrees with **no model call**. It is a plain request, not an operation.
  - The note is required unless a name is given; it becomes `## Initial Request` and, when `Name` is blank, its first line names the workspace (`quickWorkspaceName`, capped at `DERIVED_NAME_MAX_CHARS`). Naming (`sanitizeSlug`, `workspaceDirName`, `deriveBranchName`) lives in the pure module `@/lib/naming` so the form previews the server's own result.
  - Picker lists cloned repos (`listSelectableRepositories`); base branches shown offline (`localBaseBranch`). Creation uses `detectBaseBranch`.
  - A PR URL entry (`parsePrUrl`, `@/lib/github-pr-url`) becomes a worktree of the PR's head branch (`resolvePrBranch`); its title can name the workspace, and its URL/title/body go into `## Initial Request`. Unreadable/fork/duplicate PRs are `problems`; no name at all is a `QuickCreateRefusal` (400).
  - Only the title and `## Repositories` are filled (`fillQuickReadme`), declaring only worktrees that exist. Contract sections and TODO files stay empty. A failed repo is reported, not fatal; when one fails the page reports and offers links instead of navigating.
  - On success it navigates straight into a `task` chat (see **Chat**). Exception: task type `review` with at least one resolved PR starts `/api/operations/review` and navigates there.
- **`/new` form** — `NewWorkspaceForm` POSTs the operation itself and clears the form on success (keeps input on refusal). Picked repos are appended under `## Selected Repos` (`withSelectedRepositories`, `@/lib/task-description`), which `init-readme` reads additively. A blank description with repos ticked composes to nothing.
- **Started operations** — `/new` and `/suggestions` pass no `storageKey` to `ClaudeOperation` and do not navigate; the sidebar indicator finds the run. Pages whose purpose is one operation (`utilities/*`, `suggestions/discover|aggregate|prune`) keep a `storageKey`.
- **Toolchain pre-warm** — `Prepare toolchain` (after `Discover repo constraints`) starts environment-touching constraint commands (`Toolchain`, `Install`, `Submodules`, `bootstrap`, …; not `Codegen` / `Format` / `MSW`) fire-and-forget; `execute.ts` awaits them before spawning executors (`workspace/toolchain-prewarm.ts`). Failure is reported, never fatal.
- **Constraint discovery** — `buildDiscoverConstraintsPhase` writes `## Repository Constraints` into the README. It must probe each tool cheaply (`<invocation> --version`) and record the invocation that worked (exec prefix included); it never runs lint/test/build. It skips repos the README already declares. Repos added later (`update-readme`'s / autonomous's `Ensure repositories`) are discovered via `discoverConstraintsForNewRepos` using `setUpRepos` from `syncReadmeRepositories`. Results are cached per clone at `.ai-workspace/repo-constraints/<repo path>.md` (`workspace/repo-constraints-cache.ts`), keyed on blob hashes of the files discovery reads (lockfile presence only; command-bearing parts of `package.json` / `go.mod` only). Quick create reads the cache. Bump `FINGERPRINT_VERSION` when key rules change; delete an entry to force rediscovery (e.g. a stale exec prefix).
- **TODO tab** — lists repositories the README declares, not just files: a repo with no `TODO-*.md` gets a `No TODO file` card that starts `autonomous` with `startWith: "execute"` (salvage phases plan it properly). Matching by worktree directory name, alias as fallback.
- **TODO normalization** — `normalizeTodoCheckboxes()` fixes LLM formatting; `stripCompletedTodoItems()` removes `[x]` items before update-todo.
- **Workspace archiving** — `workspace_archives` table; `POST /api/workspaces/[name]/archive` toggles. Dashboard filters via `recentOnly` / `includeArchived`.
- **Repository prune** — `/utilities/repository-prune` (`workspace/repository-prune.ts`, `GET`/`POST /api/repositories/prune`). A clone is deletable when `git worktree list --porcelain` shows no live worktree besides its own (README declarations don't count). Fails closed on unreadable clones. Last-used time comes from `.git/FETCH_HEAD`, `.git/worktrees`, `.git`. Usage is re-checked on POST. Own route so the repo picker stays cheap.

### Operations

- **Batch & autonomous chaining** — batch pipelines chain init → execute → review → create-pr; autonomous loops execute → review → gate up to `maxLoops` (API default 3). `startWith` selects the first phase.
- **README clarity gate** — fresh autonomous `init` runs `Analyze README clarity` (`buildReadmeClarityGatePhase`, `autonomous.ts`; label `README_CLARITY_PHASE_LABEL`, used by the Slack notifier) after drafting. Cycle 1 is appended only if the README is a clear, grounded contract; otherwise the run stops gracefully recommending update-readme. Fails open.
- **Criteria feasibility gate** — `prepareCriteriaFeasibility()` (`pipelines/actions/criteria-feasibility.ts`) judges whether each `(auto)` criterion is achievable in these repositories. Runs as a second child of the clarity gate's group on autonomous init (verdict discarded if the clarity gate stops), and as `update-readme`'s trailing `Check criteria feasibility` phase. Not run on execute/update-todo starts. Infeasible criteria go to the known-findings ledger as `infeasible`; the run continues. Returns `null` with no `(auto)` criteria. Fails open, biased to feasible.
- **Coordinator contract audit** — `coordinator.ts` (the only agent reading every repo) resolves `[CROSS-REPO]` placeholders and audits both sides of each boundary field (cardinality, nullability, ordering, timestamp encoding incl. fixtures, ID types, prefix normalization), flagging unsatisfiable acceptance criteria under `## Coordination`.
- **Plan review is applied** — `Review TODOs` (`pipelines/actions/review-todos.ts`) returns a structured verdict (`TODO_REVIEW_SCHEMA`, `parseTodoReviewVerdict`); a trailing reviser child (`UPDATE_TODO` step, `buildTodoReviewResolutionInstruction`, `Edit(TODO-*.md)` only) turns every finding into a TODO amendment or `[!]` item. The reviewer is read-only; it checks targets against `## Non-Goal`, flags human-only `Verify`, and states risks as defects. Falls back to appending findings as `[!]` (`formatUnresolvedFindingsSection`). Blocking findings go to `emitAsk` only at `interactionLevel: "high"`.
- **Known-findings ledger** — `artifacts/known-findings.md` (`workspace/known-findings.ts`): findings deliberately not acted on. Written by the autonomous gate (`dismissedFindings`), the feasibility gate, and `knownFindingsFromGroundings`. Read by the code reviewer, cross-repo reviewer and the gate. Entry: `- **[kind]** (cycle N) summary` + `Why not acted on:`; kinds `out-of-scope` / `pending-human` / `infeasible` / `pre-existing` / `low-confidence` / `deferred` (unknown ⇒ `deferred`). Dedup on lowercase alphanumerics of the summary.
- **Gate loop bar (Suggestion budget)** — the deliverable is a review-ready branch. `shouldLoop: true` requires a Critical/Must-Fix/Should-Fix finding, an unmet actionable `(auto)` criterion, a pending in-scope TODO item, or an unlanded requested fix — the same bar every cycle. Suggestions never loop; they are recorded `deferred`. Missing test coverage is Should-Fix only for contract-required or reachable behavior; an untested defensive guard is a Suggestion. Severity must not be down-labelled to fit the budget.
- **Completion Bar** — `create-pr` is appended only when nothing above remains (`[!]` items, deferred Suggestions and `(manual)` criteria don't block). Reaching `maxLoops` with work outstanding stops with `FINAL_CYCLE_STOP_PREFIX` (`autonomous-gate.ts`), relayed by Slack via `extractIncompleteStop`; the final cycle's gate is evaluated like any other.
- **One cycle shape** — a loop always appends `Cycle N: Update TODO` → `Cycle N+1: Execute` → `Review` → `Gate`, with the full reviewer set. `fixableIssues` is the Update TODO instruction. Fix rounds are narrowed only by the incremental review baseline. Do not add a reduced-review shortcut.
- **Repositories finish independently** — the gate returns `unfinishedRepositories`; later cycles' per-repo work (`stripCompletedTodosFromWorkspace`, update-todo, execute, review) takes that set (`selectRepos`, `workspace/select-repos.ts`). Finished repos stay in cross-repo inputs and `baseline.json`; the gate gets their last reports (`describeRepositories`). `resolveUnfinishedRepositories` fails toward open (no/empty/invented list keeps all open; a repo with `[ ]`/`[~]` items stays open). PRs are created at the end; a stop creates PRs for finished repos only.
- **Requested-fix verification** — when the gate set `fixableIssues`, the next review spawns `verify-fixes-<repo>` (`fix-verifier.ts`) writing `VERIFY-FIXES-*.md` with `LANDED` / `PARTIAL` / `NOT LANDED` per ask (asks read from `gateHistory` at run time). No quality findings. Outranks TODO checkboxes; unlanded asks force a loop unless the gate retires them with a quoted reason. The collector lists statuses outside severity counts.
- **Constraint execution has one owner** — lint/test/build run only in review's `Verify constraints` phase (first in `buildReviewPipeline`, so `CONSTRAINTS-*.md` exists for the README verifier, which must not re-run them). `checkPreExisting()` classifies pre-existing failures. The code reviewer reports coverage gaps only. No declared constraints ⇒ `buildNoConstraintsReport()` writes `NOT DECLARED`. Commands run sequentially and stop on the first timeout.
- **Incremental review scope** — `review.ts` writes each repo's HEAD to `artifacts/reviews/<ts>/baseline.json` (`workspace/review-baseline.ts`); the next review uses the newest baseline strictly older than itself. `getIncrementalChanges()` (`workspace/pr.ts`) gives the code reviewer full-branch context (not reviewed) plus `<sinceSha>..HEAD` restricted to paths the branch touches as the target. Baseline dropped if not an ancestor of HEAD. Full scope always: constraint verification, README verification, first review. The cross-repo reviewer gets the same `reviewScope`: a boundary is in scope when either side changed; if every repo has a range and none moved, only recurring findings are asked for (`boundaryScopeSection`, `cross-repository-reviewer.ts`).
- **Re-reviewing a moved PR** — `refreshFromRemote` (review API flag; `Re-review` menu; Reviews tab banner) prepends `Refresh worktrees` (`actions/refresh-worktrees.ts`, `workspace/worktree-refresh.ts`), which fetches and fast-forwards each worktree onto its upstream; the review is built in a deferred phase afterwards (`buildDeferredReviewPhase`; early return in `buildReviewPipeline`). Opt-in, never under autonomous. Best-effort: dirty worktrees untouched, always returns success, a reset saves the old head to `refs/aiw-refresh-backup/<sha>`. The banner (`workspace/review-freshness.ts`) compares `baseline.json` against the PR's `headRefOid`; absence never counts as a difference.
- **Resolve base conflicts** — `resolve-base-conflicts` (TODO tab button) merges each open PR's base into its worktree with `git merge --no-ff`, hands conflicts to one agent per repo (`conflict-resolver.ts`, never commits/pushes), then commits and pushes. Deterministic parts in `workspace/base-merge.ts` (`GitExec` seam). Done-ness is judged against the PR's pushed `headRefOid` (`unpushed` / `stale` stages); the base is fetched with an explicit forced refspec. `finalizeConflictedMerge` aborts on unmerged paths or staged conflict markers. Refuses: worktree not on the PR's head branch, merge in progress, dirty worktree; a non-conflict merge failure is rolled back. No force push. Three phases (`Merge base branches` → `Resolve conflicts` → `Commit and push`) share a `MergeRun`; the first two return `true` on repo-level problems. Not under autonomous; disabled while an operation runs. Does not run lint/test/build.
- **PR review threads answered on push** — "Address PR Reviews" (`address-pr-reviews.ts`) records each triaged comment as a row under `## PR Review Threads` in the TODO file (thread id, URL, summary, item first line) and never replies itself. `create-pr.ts` reads it (`extractPrReviewThreadsSection`) and, after a successful push, replies to and resolves threads whose item is `[x]` or gone; others are untouched. Already-resolved threads are skipped. The updater must not delete the section. Reply text describes the pushed code.
- **PR title** — new PRs use the README `# Task:` heading verbatim (`workspace/pr-title.ts`, `## PR Title` section), with `[TICKET]` prefixed by `applyTicketPrefix` (only Jira/Linear, `#42`, `org/repo#42` shapes; not doubled). With no usable heading (`TBD` / `Untitled`), a branch with exactly one non-wip commit uses its subject (`getSoleCommitSubject`, two-dot range). A repo-convention prefix may precede the title; appending the repo name is forbidden. Existing PRs are not retitled. `init-readme`'s heading limit is 70 chars.
- **PR body** — `### PR Description: An Overview, Not a Walkthrough` (`pr-creator.ts`): a few sentences (under ~10 lines descriptive), describing the final state, nothing the diff shows. Without a repo template the body is exactly `## Summary` + `## Related Resources` (dropped if empty). A repo template wins; empty sections get one line or `N/A`. Updating replaces sections rather than appending.
- **Operation result box** — `extractResultSummary` (`parsers/stream.ts`) keeps one result per `childLabel` of the final phase; `operation-card.tsx` renders each. Per-child list omitted for single-child phases. The card prefers re-deriving from the event stream over the stored item; collapsed cards use the list item.

### Pull Requests tab

- **Listing** — `pull-requests-view.tsx` / `pr-review-thread.tsx`; `listWorkspacePullRequests` (`workspace/pr-threads.ts`) reads each worktree's own-branch PR via `gh pr view` + one GraphQL query. Items have `kind`: `review-thread`, `comment` (`IC_…`), `review` (`PRR_…`) via `parseConversationComments`; empty-body and `PENDING` reviews skipped; minimized comments count as resolved. Branch on the two conversation kinds, not on `review-thread`.
- **CI** — `statusCheckRollup` from the same query; `parseStatusChecks` maps to `PrCheckState`: `IN_PROGRESS` ⇒ running; `QUEUED`/`WAITING`/`PENDING`/`REQUESTED`/unknown status ⇒ queued; legacy `PENDING` ⇒ running, `EXPECTED` ⇒ queued; `TIMED_OUT`/`ACTION_REQUIRED`/`STARTUP_FAILURE` ⇒ failure; `SKIPPED`, `CANCELLED` as themselves; `NEUTRAL`/`STALE` ⇒ unknown. Summary carries `counts` for all states; headline failing → running → queued → passed → "no result". Absent rollup ⇒ `reported: false` ("CI: unknown").
- **Cache** — `pr-cache.ts` caches a promise per workspace on `globalThis` for `PR_CACHE_TTL_MS` (60s); rejections are not cached; `?refresh=1` bypasses. Validations are not cached; operations never read through the cache.
- **Validate** — `validate-pr-comments` (`pipelines/validate-pr-comments.ts`): one read-only child per selected thread (`pr-comment-validator.ts`, `allowedTools: ["Bash(git:*)", "Bash(gh pr view:*)"]`) returning `valid` / `invalid` / `unclear` + reasoning/evidence, merged into `artifacts/pr-validations.json` (`workspace/pr-validations.ts`). Unparsable ⇒ nothing stored. Threads resolved against the live PR at run time. `maxRetries: 0`; budget `validatePrCommentsBudgetMs` per thread. Disabled for check-only selections.
- **Triage** — `buildTriagePrCommentsInstruction` → `autonomous` with `startWith: "update-todo"`, folding recorded verdicts in; overriding `invalid` is allowed. Failing checks (`isTriageableCheck`, `failure` only) are selectable; their logs are fetched on click via `POST /api/workspaces/[name]/pr-check-logs` (`workspace/pr-check-logs.ts`: `gh run view --job <id> --log-failed`, fallback `--log`; tail 150 lines / 10k chars; prefix stripped). Unreadable logs don't block. The CI instruction lets flaky/infra failures go under `## Notes`. Conversation comments and checks get no `## PR Review Threads` row. A single-repo selection passes `repo` to autonomous (also drops the cross-repo reviewer); multi-repo falls back to the whole workspace. The action bar shows the scope.
- **Chat** — opens a `discussion` chat with `buildPrChatTopic` (`@/lib/pr-chat-topic`) as the topic; always a new session.
- **Notes** — each ticked item has a note (`sessionStorage`, `@/lib/pr-notes`) passed to all three buttons; in Triage it outranks the validation's recommendation. A started triage drops the notes it carried.
- Validate and Triage are disabled while any operation runs on the workspace.

### Review tab

- **Sessions sidebar** — `ReviewSessionList` (`review-session-list.tsx`) in the left column (`review/layout.tsx`), `max-content` width, `aria-current="page"` on the active row. Per-repo reports are listed by name/size (`getReviewFileList`) and read lazily through the artifacts file route when a `ReviewReportSection` opens. `getReviewDetail` still returns contents for the gate.
- **Posting findings** — the code reviewer also writes `FINDINGS-<org>_<repo>.json` (`review-findings.ts`; fail-soft parsing; unknown severity ⇒ `suggestion`, missing confidence ⇒ `medium`). `review-findings-list.tsx` lists them; pre-ticked = Critical/Warning at ≥ medium confidence, not previously declined. `post-review-findings` (`pipelines/post-review-findings.ts`) spawns one read-only grounder per finding (`finding-grounder.ts`) judging `holds` and `scope` (`pr` / `local-only` / `pre-existing`); unparsed fields fall back to not posting (`normalizeHolds` / `normalizeScope`). Comments are written in the target repo's conventions (sampled from the PR's own review comments, 6 / 1200 chars; fallbacks CONTRIBUTING, template, commits, English); `buildCommentBody` prepends nothing. A trailing deterministic phase posts one review per repo; children never post. Verdicts persist to `artifacts/finding-groundings.json`. Anchors resolved beforehand (`diff-anchors.ts`: `inline` / `file` / `pr-body`). Idempotent via `<!-- aiw-finding:<id> -->` markers (scanning PR comments and pending reviews; id hashes the body's first line). Review left pending by default; an existing pending review is reported. Requests carry finding ids only. Disabled while an operation runs. The cross-repo reviewer writes no findings file.
- **Carry posted findings** — `carryPostedFindings` (review route only) feeds this workspace's posted, grounded findings (`workspace/posted-findings.ts`) per repo to `verify-fixes-<repo>` (`askSource` distinguishes them from gate asks; `requestedFixes` wins). Declined findings (`shouldPost` false) go to the ledger: refuted/unsettled ⇒ `low-confidence`, confirmed pre-existing/local-only ⇒ `pre-existing`.

### Other tabs

- **Changes** — `changes-browser.tsx`: per-repo file trees (`buildFileTree`, `@/lib/file-tree`) beside all diffs in one list (`UnifiedDiffViewer`). Compares the working tree (plus untracked) against `merge-base(origin/<base>, HEAD)` without fetching (`workspace/changes.ts`, `GET …/changes`, `…/changes/diff?repo=&path=`); base is the README's if that ref exists, else `localBaseBranch`. Diffs load lazily (`IntersectionObserver`, `LOAD_AHEAD_MARGIN`) and are kept; only listed paths are readable; cut at `CHANGES_DIFF_MAX_BYTES`; not revalidated on interval/focus. Columns scroll independently; the tree follows the list without fighting manual scroll. Selected lines get a `ChangeComment` (`@/lib/change-comments`, `sessionStorage` via `useChangeComments`), rendered inline via a Monaco view zone spacer + overlay widget (`DiffZone`), placed by `anchorComment` (unplaceable comments stay in the list only). Exits: `Talk in chat` (`buildCommentsTopic` → `discussion` chat) and `Make TODOs` (`buildChangeCommentsTodoInstruction` → autonomous `startWith: "update-todo"`, `repo`-scoped when single-worktree, every comment must be non-empty, disabled while an operation runs). Cleared only when the operation started.
- **Artifacts** — `artifacts-browser.tsx` renders the whole `artifacts/` tree read-only via `listArtifacts` / `readArtifact` (`workspace/artifacts.ts`), `GET …/artifacts` and `…/artifacts/file?path=`. `resolveArtifactPath` is the only entry: rejects absolute/`..` paths and compares realpaths; the walk skips symlinks; refusals and misses are both 404. Reads bounded by `ARTIFACT_MAX_BYTES`; null byte ⇒ binary, no content. Tree is a flat array in tree order; top-level dirs and ancestors of `?file=` start open.
- **Memo** — `artifacts/memo.md` in Monaco (`memo-editor.tsx`), autosave every 60s + on navigation; module-level cache; "Update TODO" toolbar action. `GET/POST /api/workspaces/[name]/memo`.
- **Workspace sidebar** — each row may show an operation indicator (`useRunningOperations`: pending ask, running, or usage-limit stop) and a chat indicator (`useChatSessions`; busy / waiting / unknown; absent with no session). Indicators are links (operation → `?operationId=`, preferring the one with `hasPendingAsk`; chat → `chat/interactive`); the row link is an overlay so they can nest. Usage-limit stops come from `listUsageLimitStops` (`operation-store/usage-limit.ts`, `GET /api/operations/usage-limit`): the workspace's latest operation (`listLatestOperationPerWorkspace`, running included) is `failed` with a `resultSummary` matching the CLI's limit wording (narrow match). Label is the CLI message verbatim.

### Chat

- **PTY size** — the browser's xterm owns it: spawn at the size from `start`, `resize` → `terminal.resize()`. `useTerminal`'s `init()` awaits the fit; refit via `ResizeObserver` on the container; a resumed session resizes after `replay_done` and only if different. Sizes clamped by `clampPtySize` (`src/lib/pty.ts`).
- **Opening message is pointers** — `templates/prompts/chat.ts`: names the workspace path and files; the first turn is `cd` → one `Read` of `README.md` (+ `SUMMARY.md` for review/research) → a short acknowledgement and wait. `handleStart` refuses (with an `error` frame, before killing an existing session) when `README.md` is missing; a caller `initialPrompt` bypasses both.
- **Variants** — `chat`, `review-chat`, `research-chat`, `task`, `discussion`, chosen in `buildChatOpening`. `task` (quick create; `buildTaskChatPrompt` / `getTaskChatSystemPrompt`) appends the note under `### What I want to do` and starts working without asking. Its first turn first rewrites the README `# Task:` heading (≤ 70 chars) and `## Goal` (English; other contract sections and TODO files untouched). It never pushes, opens PRs or merges unless asked. Whitespace-only task ⇒ plain chat. `discussion` (`getDiscussionChatSystemPrompt` / `buildDiscussionChatPrompt`) reads the README and the referenced code, summarizes each item briefly, and waits; replies on GitHub and changes wait for the user.
- **Handoff** — start options (task, discussion topic, `reviewTimestamp`, `researchChat`) go through `stashChatHandoff` (`@/lib/chat-handoff`, `sessionStorage` per workspace), not the URL. Read without consuming; cleared on `onHandoffDelivered` (session started with it or a saved session resumed). Expires after `CHAT_HANDOFF_TTL_MS`. A task applies only to a session this mount starts; review/research/discussion always start a new session.
- **Busy detection** — `isSessionBusy` (`chat-server/activity.ts`): `progress.inFlight !== false && now - lastOutputAt < CHAT_BUSY_IDLE_MS` (3s). `inFlight` tracks the latest OSC 9;4 marker (`readTurnProgress`, split-chunk safe); unknown ⇒ silence alone decides. `lastOutputAt` seeded with `startedAt`. Reported as `busy` by `handleSessionsList`; `useChatSessions` polls every 2s; an absent `busy` is `unknown`, never waiting. A workspace with several sessions reports the busiest.
- **Waiting notification** — `chat-server/waiting-notifier.ts` (timer `CHAT_WAITING_POLL_MS`) uses `takeSessionsTurnedWaiting` (same predicate) to push `sendChatWaitingNotification`. Keyed on `lastOutputAt` (one notification per wait); requires `CHAT_NOTIFY_MIN_WORK_MS` between `lastInputAt` and `lastOutputAt`; exited sessions are skipped.

### Slack bot

Optional Socket Mode bot (`bin/slack-server.ts`; code in `src/lib/slack-server/`, handler + `handleConversation` in `index.ts`). Handles `app_mention` only; non-allowlisted users (`slack.allowedUserIds`) are dropped.

- **Commands** — `init <desc>` → `/api/operations/autonomous` (`startWith: "init"`); `init --only <desc>` → `/api/operations/init`. Both force `interactionLevel: "low"`. Anything else (not `init`/`help`) is conversation (`parseCommand` → `kind: "chat"`).
- **Completion notification** (autonomous only) — `notifier.ts` polls every 30s (mapping in `slack_pending_notifications`), extracts PR URLs from the `Create PR` phase (`extractPrUrls`, minus URLs in the description). Clarity-gate stops (`extractClarityGateStop`, `README_CLARITY_STOP_PREFIX`) and final-cycle stops (`extractIncompleteStop`, with `withCreatedPrs`) are relayed instead of "no PRs". Failed runs are dropped silently.
- **Thread link** — a mention in a thread appends the root's permalink (`mergeWithThreadLink()`, `thread-link.ts`); the thread body is not inlined.
- **Conversation** (`conversation.ts`) — `runClaude` at the workspace root with `skipAskUserQuestion` and no `allowedTools`/`addDirs` (ambient permissions). Policy is prompt-only (`getSlackChatSystemPrompt()`, `templates/prompts/slack-chat.ts`): read-only by default; writes only on explicit request (prefer MCP); never git/codebase changes or destructive actions. Files go only in `.ai-workspace/slack-scratch/<threadKey>/` (`getSlackScratchDir()`, `chat-scratch.ts`; computed, not created; key sanitized); `workspace/`, `repositories/` and the rest of `.ai-workspace/` are read-only, and PR review/new work is routed to the WebUI or `init`. `buildSlackChatPrompt()` sends full instructions on the first turn only. Model/effort from `slack.chatModel` / `chatEffort` (sonnet/medium).
- **Sessions** — `session_id` keyed on `thread_ts ?? ts` (TTL 2h, cap 200) in `slack_conversation_sessions` (`db/slack-sessions.ts`); follow-ups `--resume`. A resumed turn failing with no output/non-zero exit retries once fresh (only on `reason === "error"`).
- **Progress** — every `chatHeartbeatMs` the assistant text (`getAssistantText()`) is summarized by `summarizeProgress()` (`progress-summary.ts`, `chatProgressModel`, 30s timeout) and shown via `formatProgress()` by editing the placeholder (guarded by `finished`, one summary in flight). Killed only at `chatMaxTurnMs`; the session id persists for resume.
- **Per-user memory** (`slack.memoryEnabled`, default true) — separate `.ai-workspace/slack-memory.sqlite` (`ensureSlackMemoryDb()`, `memory-db.ts`), operated by the model via `sqlite3` CLI per instructions in the first turn; scoped by `user_id`; writes only to `memories`, only on request.
- **Thread folding** — the first conversation mention in an existing thread fetches the transcript (`fetchThreadTranscript()`, `thread-fetch.ts`, cap 50×200) into the first turn. Needs `*:history` scopes; proceeds without on failure.

### Prompt conventions

Shared fragments live in `src/lib/templates/prompts/shared.ts`; compose from them rather than restating. `shared.test.ts` enforces adoption.

- **Working directory** — `worktreeCdRules({ examples, forbidden?, extra? })` for single-worktree agents (bare `cd` first; the sandbox blocks `cd <dir> && ...`). `NO_CD_RULES` for multi-directory agents (collector, coordinator, researcher). Mutually exclusive.
- **`WRITTEN_DELIVERABLE_LENGTH`** — for every agent that writes a file, including the planner. Planner items have three required fields (`Target` / `Action` / `Verify`) and two conditional (`Pattern` / `Why`); `Verify` is the acceptance condition.
- **Planner item count** — `### What Is Not a TODO Item`: no "read this doc" items, no per-constraint-command items (narrowest proving command goes in `Verify:`; at most one trailing whole-set item). `todo.ts` templates follow the same shape.
- **`REPO_SEARCH_EFFICIENCY`** — use `Grep`/`Glob`/`Read` (incl. `offset`/`limit`) instead of shell search/slicing, and issue independent lookups as several tool calls in one turn (not `;`-packed commands). Non-exhaustive shell→tool table; rendered after the cd rule. Planner and plan reviewer.
- **`SUBAGENT_DELEGATION_POLICY`** — when to delegate; never to verify one's own output. Agentic steps.
- **`SCOPE_DISCIPLINE`** — deliver the requested scope, finish rather than stub; a cited pattern governs form, not extent. Executor and TODO updater. The updater's `### Deriving an Item's Targets` (right after it) requires enumerating every doc site that states a changed contract (interface declaration included) and test items covering every changed site.
- **`TOOLCHAIN_RESOLUTION`** / **`NO_TICKET_IDS_IN_CODE`** — for code-writing agents (executor today); toolchain problems are not a reason to give up.
- **`NO_WORKSPACE_REFERENCES`** — nothing landing in a repo or PR may reference the workspace or its process (cycles, TODOs, findings, reports). State the substance or omit it. Allowed references: the repo's files, commits, PRs/issues, given ticket URLs. pr-creator, finding grounder, executor.
- **`REVIEW_COVERAGE_POLICY`** — reviewers report everything with `(Confidence: high|medium|low)`; the collector preserves annotations; the gate's `### Confidence Filtering` filters (low alone never loops, missing ⇒ medium). Confidence measures whether the mechanism is real, not how likely the input is. Reviewers and collector must not issue ship/merge verdicts (`## Conclusion` templates enforce this; no Overall Assessment row).
- **`SEVERITY_CALIBRATION`** — Critical = broken; Warning = unfinished/unsound (unhandled failure path, contract gap, cross-boundary mismatch, an input class the replaced code handled and the new code doesn't — with a fallback fix attached); Suggestion = taste. Untested paths: contract-required or previously asked ⇒ Warning; reachable otherwise ⇒ Suggestion; unreachable defensive guard ⇒ Suggestion. A construct with other pre-existing sites in the repo (`new but not novel`) is a Suggestion listing those sites unless this use is specifically wrong. Cost of covering is reported, never scored. Code reviewer and cross-repo reviewer.
- **`RECURRING_FINDINGS_POLICY`** — ledger findings are still reported as one `(Recurring)` line outside severity counts (unless materially changed). Travels with `REVIEW_COVERAGE_POLICY`. `knownFindingsSection()` renders the ledger.

Wording: prefer a positive example over stacks of "Do NOT"; mark example lists non-exhaustive; no "double-check your work" instructions.

## Development Rules

- **Never start, stop or restart the server** unless explicitly asked. A dev instance with hot reload is normally already running against this directory; find its port with `pgrep -fl "bin/start.ts"`. Starting a second one creates `.ai-workspace/` in its resolved root and prompts on stdin (hangs non-interactively).
- **Never `pkill -f` anything this project can also be running.** Every entry point appears in the real instance's command line, so a pattern aimed at a throwaway kills the live stack (chat sessions, running operations). Stop a probe by the pid you started. A killed instance cannot be faithfully restarted from a session (its env carries port, root and tokens) — report it and let the user restart.
- **Never block the event loop in server code.** Spawn via `runProcess` (`src/lib/process/run.ts`) or `exec` / `execArgs` (`workspace/helpers.ts`) / `runGit` (`workspace/git-exec.ts`); sleep with `await Bun.sleep()`; use `node:fs/promises`, `Bun.file` / `Bun.write`, and `pathExists` / `globScan` from `@/lib/fs`. ESLint rejects sync forms under `src/` (tests excepted). The only sync filesystem code allowed is one-time cached initialization listed in the `eslint.config.ts` override (`getConfig()`, `getDb()`, VAPID keys, Slack memory DB, `getCliPath()`, dev prewarm). When converting to async: `Promise.all` over sync work is still serial; callers must actually `await` (check with typed lint and grep call sites); `await f(x).y` is `await (f(x).y)`.
- **TDD**: write a failing test first, then implement.
- **Pre-commit checks**: `bun run lint` and `bun run test` must pass.
- **Git commands**: run `git add`, `git commit`, `git push` as separate commands; no `$()` substitution in git commands.

## Conventions

- Path alias: `@/*` → `./src/*`
- **`globalThis` pattern**: mutable state (DB, operations, config, chat sessions, locks) lives on `globalThis` to survive HMR. Tests must account for this (see `test-setup.ts`).
- **`force-dynamic`**: all API routes export `const dynamic = "force-dynamic"`.
- ESLint flat config (`eslint.config.ts`): unused vars prefixed with `_`; `bin/**` excluded.
- `bun:sqlite` is in `serverExternalPackages` (`next.config.ts`).
- Types in `src/types/`, tests in `src/__tests__/` mirroring `src/`.

## Testing

Vitest with `@testing-library/react` and `jest-dom`; globals enabled. `tsconfig.json` excludes tests.

- `vitest.config.ts` has two projects: `dom` (jsdom + `src/test-setup-dom.ts`) for `src/__tests__/components/**` and `src/__tests__/hooks/**`, and `node` for everything else. A render test outside those directories gets no `document`. `maxWorkers: "60%"`.
- An unbounded loop calling a `vi.fn()` grows `mock.calls` without limit and can exhaust memory; bound any search loop that a permissive mock could make endless (e.g. `MAX_BRANCH_NAME_ATTEMPTS`). Kill a runaway worker by pid — its command line (`vitest/dist/workers/forks.js`) has no test path.

## Gotchas

- **Lint type-checks via `tsconfig.typecheck.json`** after `next typegen`, excluding `.next/dev` (which `next dev` doesn't regenerate on route deletion). The exclusion can't go in `tsconfig.json`; `next dev` rewrites it.
- **Config is cached** — `getConfig()` caches on `globalThis`; call `_resetConfig()`. Tests reset in order: `_resetDb()` → `_resetConfig()` → `_resetWorkspaceRoot()`.
- **Event buffering is async** — don't query events from the DB right after emitting; SSE replays from memory.
- **Workspace root before config/DB** — `bin/start.ts` calls `setWorkspaceRoot()` before `getConfig()`.
- **Running vs completed operations** — running in memory (`src/lib/pipeline/store.ts`), completed on disk; `/api/operations` merges (running wins) and serves `?status=completed&limit=N` (`listRecentFinishedOperations`).
- **`runSubPhases` discards sub-phase `timeoutMs` and `effort`** — under autonomous only the wrapping phase's budget applies (`CYCLE_BUDGETS_MS`, plus `executeCycleBudgetMs()`); sub-pipeline `timeoutMs` only matters for top-level runs.
- **JSONL auto-migration** — first `getDb()` imports legacy `.operations/` JSONL if the table is empty.
- **Dev route prewarm** — `bin/next-server.ts` compiles every page route in the background after start (`src/lib/dev/prewarm.ts`, 4 at a time, dynamic segments filled with `PREWARM_PARAM_VALUE`, catch-alls skipped), then sends `OPTIONS` to route handlers (skipping any that export `OPTIONS`). `.next` is cleared only on `--hot`; other modes build when `.next/BUILD_ID` is missing.
